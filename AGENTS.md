# AGENTS.md

## What this repo is
- OpenSpec-driven project (`marketplaceb2b`): a Java 21 / Spring Boot WebFlux service skeleton (`src/`, Gradle) plus the OpenSpec tree and generated agent skills/commands.
- Git repository (remote `origin` → `diegodob/marketplaceb2b`).

## Source of truth
- `openspec/` is authoritative:
  - `openspec/specs/` — current capability specs
  - `openspec/changes/` — active changes; `openspec/changes/archive/` — completed
  - `openspec/config.yaml` — schema `spec-driven`; project-specific constraints belong under `context:` / `rules:` (currently only commented defaults)
- `openspec` CLI (v1.14.1) is on PATH. `openspec list --json` reports the resolved `root` and active changes.

## Workflow
- Drive work through OpenSpec: propose → apply → archive. Trigger via the skills (`openspec propose|apply|archive|explore|sync|update`) or slash commands `/opsx:*`.
- Planning and implementation are separated: propose creates planning artifacts only; code changes happen in a later, explicit apply request.
- Author spec/change artifacts only through the CLI-generated structure, then run `openspec validate`.

## Commits
- Use **Conventional Commits**: `feat|fix|chore|docs|refactor|test|build|ci(scope): subject`.
- Commit messages are **always in English**, imperative mood, lowercase after the type.
- Reference the OpenSpec change in the body when relevant.

## Git workflow
- The **initial commit** of a new repository may be pushed directly to `main`.
- After that, **every change goes through a Pull Request**: create a branch, push it, and open a PR.
- The maintainer (diegodob) merges PRs manually. Do **not** merge a PR unless explicitly told to.

## Gotchas
- `.claude/` and `.hermes/` hold the same generated OpenSpec skills/commands (they differ only in invocation syntax, `/opsx:...` vs `/openspec-...`). They are regenerated by `openspec` (`metadata.generatedBy: 1.14.1`) — do not hand-edit.
- Shell is Windows PowerShell 5.1: `&&` is unsupported; chain with `;` or `if ($?)`.
